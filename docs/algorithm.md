# アルゴリズムと独立実装の範囲

dagger は吉永直樹の Jagger 論文で提案された、特徴列パターンの最長一致による形態素解析を Cython で独立実装したものだ。Jagger の C++ コードや cedar の実装を取り込んでおらず、公式モデルとのバイナリ互換性や解析結果の完全一致は主張しない。

## 推論の決定規則

パターンは次の情報を持つ。

```text
(照合する表層, 任意の直前品詞) -> (切り出す文字数, 品詞, 原形の編集情報, 読み)
```

現在位置から始まる表層が長く一致するパターンを優先し、表層が同じ長さなら直前品詞の一致するパターンを優先する。最長の「単語」を選ぶのではない。照合した表層は右側の文脈を含められ、実際に切り出す単語はそれより短くてよい。たとえば `のな -> 1文字・助詞` は「な」を観察して「の」だけを切り出す。

表層 Trie を最も深くまでたどり、そこから親方向に戻って、直前品詞つきの値、直前品詞を問わない値の順で探せばこの優先順位になる。前品詞を含む特徴数を単純に比較する規則とは異なる。文頭の前品詞は空文字列で表す専用の BOS 条件だ。

## 学習

正解単語の先頭ごとに、単語全体から右に文脈を伸ばした表層を列挙する。各表層について、前品詞なしと前品詞ありの両候補で正解出力の頻度を数える。

1. 品詞を周辺化して、最多の分割長を選ぶ。
2. 選んだ分割長の中で、最多の品詞を選ぶ。
3. 同じ分割長・品詞の中で、最多の原形・読みの注釈を選ぶ。

分割長と品詞の組全体に対して一度だけ argmax を取る手続ではない。たとえば `(1文字,A)=4回`、`(1文字,B)=4回`、`(2文字,C)=7回` なら、分割長は `1文字` が `8回` で勝つ。

同数の場合は分割長が長い方を選び、品詞と原形・読みは辞書順で決める。この規則と全列挙により、同じ訓練事例の順序を変えても学習結果は変わらない。

辞書の語が訓練候補として観測されなかった場合は、その表層全体を切り出すパターンを追加する。辞書に複数の品詞があれば、訓練コーパス中の品詞頻度を事前情報として選ぶ。MeCab の生起・連接コストは使わない。

## 原形と読み

原形は、表層との最長共通接頭辞を残し、末尾を指定文字数だけ削って接尾辞を足す編集として格納する。`食べた -> 食べる` なら `strip=1, suffix=る` だ。格納時の長さは Unicode コードポイント単位なので、非 BMP 文字も 1 文字として扱う。読みは訓練データまたは辞書の値を保持し、未知の読みを生成するモデルは持たない。

## 剪定

出力が短いパターンからのフォールバックと同じ候補を取り除く。ただし、前品詞の条件を無視した剪定は誤りになる。

```text
甲       -> X
甲 + P   -> Y
甲乙 + P -> X
```

この場合、最後のパターンを「短い汎用パターンも X だから」と削ると、前品詞 P で Y が選ばれてしまう。

dagger は前品詞つき候補について実際に同じ前品詞でフォールバックを調べる。汎用候補は、親から引き継ぐ出力がすべての前品詞で一様かつ同じだと確認できる場合だけ省略する。これは保守的な剪定であり、候補を多めに残すことはあっても、剪定前の決定規則を変えない。

## 論文・公式実装との差分

| 項目 | dagger の仕様 |
| --- | --- |
| 学習時の右文脈 | 上限まで全列挙する。公式実装にある、初めて見た表層でその回の延長を止めるヒューリスティクスは使わない |
| 上限の自動設定 | 辞書とコーパスの最長単語の長さを使う。辞書より長い正解語も落とさない |
| `max_pattern_chars` 指定 | 右文脈の上限を制限する。ただし、上限より長い正解語の全体は保持する |
| 品詞と語彙情報 | まず品詞を周辺化して決め、その後に原形・読みを選ぶ |
| `min_count` | 候補全体の出現数の下限。既定値は 1。増やすと学習内容が変わる |
| 剪定 | 前品詞の影響を残す保守的な剪定。公式版と同じパターン数になるとは限らない |
| モデル形式 | 独自のモデル形式。Jagger のモデルファイルとは互換でない |

入力のデータ型・レコード形状は検証する。学習用コーパスと評価用コーパスは明示的に分け、学習器が評価用ファイルを自動的に読むことはない。

## メモリと学習速度

抽出ループは Cython でコンパイルし、表層の prefix を整数 ID の Trie で共有する。観測のたびに長い Python 部分文字列や Counter を作る構成を避け、頻度は整数のキーを持つ C++ のハッシュ表で集計する。ここで使う C++ コンテナは Cython 標準の `libcpp` 経由であり、別の解析器へのバインディングではない。

全列挙の計算量は単語開始位置数と右文脈上限に比例するが、語ごとの表層走査と結果の構築も必要だ。訓練データや上限が大きければモデル構築時のメモリ消費は増える。メモリに制約がある場合は `max_pattern_chars` で上限を下げ、開発データで精度を確認する。入力文の過度な長さ自体を学習器が切り捨てることはない。

## 静的配置による独自の最適化

特徴列による判定規則は Jagger の手法に基づく。一方、dagger のダブル配列の構築は独自の静的配置だ。ソート済みのキーから最長共通接頭辞を共有する論理 Trie を作り、子の数が多いノードから子群を配置する。親の物理的な配置位置は最後に解決するため、木の深さ順に配置する必要はない。子が 1 個だけのノードは最後に空きを埋める。

空きスロットは双方向リストで管理する。同じ分岐数の子群は、前回成功した位置の先から空きを探し、分岐数が下がったときに先頭の空きへ戻る。これにより、適合しない同じ穴を毎回調べて末尾へ逃げる配置を避ける。キーの昇順・一意性も構築時に検証する。

KWDLC と辞書から抽出した同じ 742,868 パターンで、初期の深さ順配置は 6,932,545 スロット、改良後は 1,553,247 スロットとなった。スロット数は約 77.6% 減り、有効ノード 1,152,989 に対する占有率は約 74.2% となった。この配置変更は照合規則とラベルを変えない。開発環境での改良後の構築時間は約 5.56 秒、モデル全体は 47,016,496 bytes だった。これらは dagger 内部の配置方法の比較であり、Jagger より速いという測定結果を意味しない。
